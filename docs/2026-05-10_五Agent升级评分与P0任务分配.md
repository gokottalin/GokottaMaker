## 本轮检查结论

本地代码状态干净，`npm run check:version` 通过，核心 JS 语法检查通过，`scripts/verify-api.ps1` 通过登录、CSRF、轮播排序、上传、文章/项目 CRUD、导出、sitemap、RSS 和退出流程。

发现 2 个必须优先处理的问题：

1. 云端 `http://81.71.156.122:4173/healthz` 当前返回 502，说明线上服务或反向代理不可用。
2. 本地 SQLite 轮播数据仍存在历史越界排序：`post:opensource-power-amplifier:4`，当前规则只允许 0-3 且首页最多 4 个轮播内容。

这两个问题会直接影响发布可信度和首页轮播一致性，归入 P0。

## 评分机制

评分总分 100，按以下权重计算：

| 维度 | 权重 | 判断重点 |
|---|---:|---|
| 上线可用与数据安全 | 30 | 是否影响线上访问、备份恢复、图片与数据库持久化 |
| 核心编辑与访客体验 | 25 | 是否影响管理员维护内容、访客阅读与首页展示 |
| 可维护性与 Agent 协作 | 20 | 是否会阻塞多个 Agent 并行开发或造成冲突 |
| 内容增长与 SEO | 15 | 是否影响后续内容体系、搜索收录、RSS/sitemap |
| 执行独立性与风险 | 10 | 是否可独立交付、可验证、可回滚 |

优先级定义：

| 优先级 | 分数 | 含义 |
|---|---:|---|
| P0 | 90-100 | 立即处理，影响上线或核心闭环 |
| P1 | 75-89 | 下一轮处理，影响长期效率和质量 |
| P2 | 60-74 | 计划处理，属于增强与治理 |
| P3 | 0-59 | 后续优化，非阻塞 |

## P0 执行顺序与 Agent 分配

### 1. Agent1：云端服务恢复与发布健康闭环

执行顺序：第 1 位。

输入：

- 当前提交：`6057470`
- 当前版本：`V2.4.1+20260509-2145`
- 云端入口：`http://81.71.156.122:4173/`
- 部署脚本：`scripts/deploy-update.sh`
- 健康检查：`/healthz`

输出：

- 云端恢复报告，包含 `systemctl status`、`journalctl` 关键错误、备份目录、部署前后版本对比。
- 成功时输出云端 `/healthz` JSON。
- 失败时输出最小复现和回滚命令。

验收：

```bash
curl -fsS http://127.0.0.1:4173/healthz
curl -fsS http://81.71.156.122:4173/healthz
```

云端结果必须包含：

- `ok: true`
- `versionLabel: V2.4.1+20260509-2145`
- `gitCommit: 6057470`

### 2. Agent2：轮播数据一致性与上传路径巡检

执行顺序：第 2 位，必须在 Agent1 确认服务可运行后执行。

输入：

- `scripts/check-carousel-db.js`
- `scripts/cleanup-carousel-db.js`
- `scripts/check-carousel-cloud.sh`
- `scripts/cleanup-carousel-cloud.sh`
- 当前发现：`post:opensource-power-amplifier:4`

输出：

- 本地和云端轮播巡检结果。
- 如需清理，先备份 DB，再执行 cleanup。
- 上传路径检查结果，确认数据库 cover 字段指向的图片都能公开访问。

验收：

```bash
node --experimental-sqlite scripts/check-carousel-db.js --db database/gokottamaker.sqlite
bash scripts/check-carousel-cloud.sh
```

结果必须满足：

- 首页轮播总数 `<= 4`
- 无重复 slot
- 无 `featured_order < 0` 或 `featured_order > 3`
- 上传图片 URL 可访问

### 3. Agent3：CMS 内容蓝图与编辑工作流稳定化

执行顺序：第 3 位，依赖 Agent2 的数据规则稳定。

输入：

- `admin/index.html`
- `admin/admin.js`
- `admin/admin.css`
- 当前轮播规则：固定 4 个槽位，排序只允许 0/1/2/3
- 当前用户偏好：内容蓝图在上方；左预览、右编辑；文件选择按钮同风格；收起编辑器后预览铺满。

输出：

- 内容蓝图排版稳定，字段对齐合理。
- 轮播排序 UI 在 1279、1366、1920 宽度下不溢出。
- 封面选择使用统一风格按钮，不暴露原生输入框。
- 编辑器收起后预览区自动扩展。

验收：

- `powershell -ExecutionPolicy Bypass -File scripts/verify-api.ps1 -Port <port>`
- 管理端 1279x589 和 1920x1080 截图无横向错位。

### 4. Agent4：访客端视觉与响应式回归

执行顺序：第 4 位，需等 Agent3 避免共享样式冲突后执行。

输入：

- `index.html`
- `main.js`
- `styles/*.css`
- `category.html`
- `projects.html`
- `miniapps.html`
- 当前用户偏好：Logo 只显示图标且放大、不带外边框；Header 加日夜模式；Hero 卡片玻璃清晰不过度模糊。

输出：

- 访客端日夜模式可用。
- Header 在桌面和移动端不拥挤。
- Hero 玻璃卡片可读、不过度模糊。
- 小程序版本显示与 `data/miniapps.js` 一致。

验收：

- 首页、分类页、项目页、小程序中心在 390、1279、1920 宽度下截图通过。
- Hero 文本对比度清晰，Logo 无外框。

### 5. Agent5：内容、SEO 与发布门禁

执行顺序：第 5 位，作为上线前最后内容检查。

输入：

- `content/posts/`
- `data/posts.js`
- `data/seed.js`
- `data/miniapps.js`
- `/rss.xml`
- `/sitemap.xml`
- `/robots.txt`

输出：

- 首页轮播 4 个内容覆盖四个方向或给出明确选择理由。
- RSS 不为空，sitemap 包含公开文章、公开项目和小程序中心。
- 文章/项目标题、摘要、标签符合内容规范。
- 给出下一批内容选题建议。

验收：

```bash
curl -fsS http://127.0.0.1:4173/rss.xml
curl -fsS http://127.0.0.1:4173/sitemap.xml
curl -fsS http://127.0.0.1:4173/robots.txt
```

RSS 和 sitemap 不能空，且不得包含草稿、回收站或规划中禁止访问详情的内容。

## 总控协调规则

1. P0 不并行全开，按 Agent1 -> Agent2 -> Agent3 -> Agent4 -> Agent5 顺序推进。
2. Agent1/Agent2 改动线上数据前必须先备份。
3. Agent3/Agent4 均会触碰视觉层，Agent3 先稳定 CMS，Agent4 再做全站视觉回归。
4. Agent5 不改 CMS 和后端逻辑，只做内容、SEO 和发布门禁。
5. Agent6/Leo 暂不进入本轮五 Agent P0，除非小程序中心本身出现线上不可用。
