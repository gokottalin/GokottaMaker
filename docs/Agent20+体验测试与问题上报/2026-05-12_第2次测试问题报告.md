## BUG-005：长文章左侧目录不能内部滚动，目录后半部分无法被游客操作

- 严重级别：P1
- 模块：游客文章阅读页左侧目录
- 复现页面：`/post.html?id=agent20-long-toc-test`
- 相关文件：
  - `styles/20-content.css:314-318`
  - `post.js:290-293`

### 复现步骤

1. 准备一篇已发布长文章，正文包含 18 个 `H2`、18 个 `H3`、18 个 `H4`。
2. 游客打开文章详情页。
3. 页面滚动到正文阅读区域，使左侧目录进入 `sticky` 状态。
4. 尝试在左侧目录中访问后半部分标题链接。

### 实际结果

左侧目录容器 `.toc-card` 只有：

- `position: sticky`
- `top: 98px`
- `padding: 20px`

运行时测得：

- `#tocList a` 数量：54
- `.toc-card` 高度：2207px
- 视口高度：768px
- 页面滚动到正文后 `.toc-card` 顶部：98px
- 最后一个目录链接底部：2284px
- 超出当前视口底部：1516px
- `.toc-card` 的 `overflow-y`：`visible`
- `.toc-card` 的 `max-height`：`none`

因此目录本身不会产生内部滚动条。游客在阅读长文章时，左侧目录后半部分会超出视口，无法通过目录区域滚动到后续小标题。

### 期望结果

长文章左侧目录在 `sticky` 状态下应限制高度并允许内部滚动，游客必须能够访问所有目录项。

### Agent0 处理要求

请让文章目录容器在桌面端具备可滚动约束，例如根据 `top` 计算最大高度；同时确保滚动条只影响目录区域，不破坏正文页面滚动。

## BUG-006：文章目录不表达 Markdown 标题层级，H2/H3/H4 被平铺成同一级

- 严重级别：P2
- 模块：游客文章阅读页左侧目录
- 复现页面：`/post.html?id=agent20-long-toc-test`
- 相关文件：
  - `post.js:290-293`
  - `styles/20-content.css:326-340`

### 复现步骤

1. 准备一篇包含 `H2`、`H3`、`H4` 的 Markdown 长文章。
2. 游客打开文章详情页。
3. 查看左侧目录的视觉结构。

### 实际结果

`post.js` 使用 `parsed.headings.filter((heading) => heading.level > 1)` 生成目录，但每个目录项都被映射成相同结构：

```html
<a href="#...">标题文本</a>
```

运行时测得文章正文存在 `H2`、`H3`、`H4`，但目录链接的层级信号全部一致：

- `className`：空字符串
- `padding-left`：`0px`
- `margin-left`：`0px`

游客看到的是一串平铺标题，无法区分一级小节、二级小节和更深层说明。

### 期望结果

文章目录应保留 Markdown 标题层级，例如：

- `H2` 作为一级目录项
- `H3` 相对 `H2` 缩进
- `H4` 相对 `H3` 继续缩进

也可以使用 `data-level`、`toc-level-*` class 或嵌套列表表达层级。

### Agent0 处理要求

请在目录生成阶段保留 `heading.level`，并在样式层为不同层级提供可识别的缩进或分组展示。

## REQ-001：MD2File 长 Markdown 缺少编辑区与预览区滚动同步 / 对齐功能

- 类型：体验缺口 / 功能需求
- 优先级：P2
- 模块：MD2File Markdown 转换器
- 复现页面：`/tools/md2doc.html`
- 相关文件：
  - `tools/md2doc.js:44-48`
  - `tools/md2doc.js:185-207`
  - `styles/md2doc.css:153-172`

### 复现步骤

1. 打开 MD2File 工具页。
2. 在左侧 `#markdownInput` 中输入或导入一篇长 Markdown。
3. 滚动左侧 Markdown 编辑区到底部。
4. 观察右侧 `#previewStage` 预览区位置。

### 实际结果

运行时测得：

- 左侧编辑区最大可滚动距离：4436px
- 右侧预览区最大可滚动距离：4401px
- 左侧编辑区滚动到底后：`#markdownInput.scrollTop = 4436`
- 右侧预览区仍停留顶部：`#previewStage.scrollTop = 0`
- 页面未出现“同步 / 对齐 / 跟随 / 定位”等可见控制入口。

源码层面也只看到 `input` 事件触发预览重渲染，没有看到针对 `#markdownInput` 或 `#previewStage` 的 `scroll` 监听与同步逻辑。

### 期望结果

MD2File 面对长 Markdown 时，应提供编辑区和预览区之间的对齐能力。至少需要满足以下一种交互：

1. 左侧编辑区滚动时，右侧预览区按相近位置跟随。
2. 右侧预览区滚动时，左侧编辑区按相近位置跟随。
3. 提供显式“同步滚动 / 对齐当前位置”开关或按钮。
4. 能按 Markdown 标题或光标所在段落定位到右侧对应预览区域。

### Agent0 处理要求

请为 MD2File 增加长文场景下的滚动同步或当前位置对齐功能，并在 UI 上提供可明确识别的启用入口。实现时需要避免左右区域互相触发滚动事件导致循环抖动。
