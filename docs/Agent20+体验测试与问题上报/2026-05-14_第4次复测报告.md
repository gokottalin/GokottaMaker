## BUG-010：390px 移动端首页课程路径区撑出横向滚动

- 严重级别：P0
- 建议归属 Agent：Agent4
- 页面：`/index.html`
- 视口：`390x844`
- 相关文件：
  - `styles/20-content.css:176-178`
  - `styles/40-responsive.css:330-356`

### 复现步骤

1. 打开 `http://127.0.0.1:4335/index.html`。
2. 将视口设为 `390x844`。
3. 检查 `document.documentElement.scrollWidth` 与 `clientWidth`。
4. 定位超出视口右侧的元素。

### 实际结果

移动端首页出现横向溢出：

```text
clientWidth = 390
scrollWidth = 461
bodyScrollWidth = 461
```

主要溢出元素来自课程路径卡片内部：

```text
.section-title-line.course-path-title-line
left = 362
right = 461
overflowRight = 71

.course-steps
left = 362
right = 461
overflowRight = 71
```

同类溢出出现在 `模拟电子 / STM32 / ESP32` 三张课程路径卡上。

### 根因判断

桌面端 `.course-path-card` 是三列：

```css
grid-template-columns: minmax(280px, 35%) minmax(0, 1fr) minmax(230px, 0.72fr);
```

响应式文件在中间断点改成两列：

```css
grid-template-columns: minmax(240px, 320px) minmax(0, 1fr);
```

但在小屏断点只调整了 padding、media、copy、side，没有把 `.course-path-card` 明确改为单列，因此右侧内容列仍被布局到视口外。

### 期望结果

390px 移动端首页必须满足：

```text
document.documentElement.scrollWidth <= document.documentElement.clientWidth + 2
```

课程路径卡应在小屏下改为单列垂直结构，不允许通过页面级横向滚动查看右侧内容。

### Agent0 处理要求

请分派 Agent4 修复移动端 `.course-path-card` 的小屏 grid。建议在小屏断点中显式设置：

```css
.course-path-card {
  grid-template-columns: 1fr;
}
```

同时确认 `.course-path-side`、`.course-path-copy`、`.course-steps` 均不会超出卡片宽度。

## AUTH-011：`/admin/course-paths.html` 未登录可访问并可写入课程覆盖配置

- 严重级别：P1
- 建议归属 Agent：Agent0 / Agent3 / Agent4
- 页面：`/admin/course-paths.html`
- 相关文件：
  - `server.js:1181-1193`
  - `admin/course-paths.html:180-182`
  - `admin/course-paths.html:212-219`
  - `admin/course-paths.html:303-305`

### 复现步骤

1. 不登录管理端。
2. 直接打开 `http://127.0.0.1:4335/admin/course-paths.html`。
3. 修改 `#routeEditor` 内容。
4. 点击 `#saveRouteButton`。
5. 打开同一浏览器上下文中的 `/index.html`。

### 实际结果

页面未显示登录表单：

```text
hasLoginForm = false
hasEditor = true
hasSaveButton = true
```

未登录状态下可以写入：

```text
localStorage[gokottamaker_course_meta_v1]
```

实测写入标题：

```text
Agent20 Unauthorized Override
```

保存后访问首页，同一浏览器中的访客端课程卡立即显示该覆盖标题：

```text
bodyContainsOverride = true
courseHeadingTexts[0] = Agent20 Unauthorized Override
```

### 影响说明

该写入不会修改服务器数据库，但它位于 `/admin/` 路径，页面文案称为“配置 / CMS”，且可以改变同一浏览器中的访客端展示，容易造成以下问题：

- 未登录游客可进入管理样式页面。
- 测试人员可能误以为课程路径已写入数据库。
- 同一浏览器后续访客页会被本地覆盖污染，导致复测结果不稳定。

### 期望结果

二选一：

1. 如果这是正式管理端功能，则必须接入管理端登录态校验，并通过受保护 API 保存。
2. 如果这只是本地预览工具，则不要放在 `/admin/` 公共路径，且页面标题和文案必须明确标注“仅当前浏览器本地预览，不会写入 CMS / 数据库”。

### Agent0 处理要求

请明确该页面的产品定位。当前状态不建议直接发布到公网可访问路径。

## ENV-012：交接文档仍是旧候选版本，且临时管理端复测命令会写入默认数据库

- 严重级别：P1
- 建议归属 Agent：Agent0
- 相关文件：
  - `docs/agent-current-handoff.md:3-4`
  - `docs/agent-current-handoff.md:114-116`

### 实际结果

当前最新可测服务为：

```text
http://127.0.0.1:4335
versionLabel = V2.4.9+20260514-1635
```

但交接文档仍写：

```text
更新时间：2026-05-13 17:59
当前候选版本：V2.4.9+20260513-1148
```

同时，文档给出的临时管理端复测命令为：

```powershell
$env:PORT='4414'
$env:ADMIN_PASSWORD='Agent20LocalTest!2026'
node --experimental-sqlite server.js
```

该命令没有设置 `DATA_DIR` 或 `DB_PATH`。按当前 `server.js` 逻辑，服务会使用项目默认 `database/gokottamaker.sqlite`，并不是隔离测试库。测试人员如果按文档执行管理端写入流程，可能污染本地候选数据库。

### 期望结果

交接文档必须更新为当前候选版本，并提供隔离数据目录启动方式。例如：

```powershell
$env:PORT='4414'
$env:DATA_DIR='.tmp\agent20-admin-retest-data'
$env:ADMIN_PASSWORD='Agent20LocalTest!2026'
node --experimental-sqlite server.js
```

### Agent0 处理要求

请更新 `docs/agent-current-handoff.md`：

1. 候选版本改为 `V2.4.9+20260514-1635`。
2. 明确推荐复测端口为 `4335`，或给出最新端口。
3. 管理端临时复测命令必须包含隔离 `DATA_DIR`。

## COPY-013：分类页空状态提示“右侧还有 4 个项目”，但右栏只展示 3 个项目

  - `/category.html?category=stm32`
  - `/category.html?category=esp32`
- 相关文件：
  - `category-page.js:224-228`
  - `category-page.js:385-392`

### 复现步骤

1. 打开 `http://127.0.0.1:4335/category.html?category=analog`。
2. 查看中间空状态提示和右侧相关项目数量。

### 实际结果

中间空状态提示：

```text
右侧项目区还有 4 个相关开源项目可先进入。
```

但右栏实际只渲染：

```text
.route-project-card count = 3
```

下方再显示“更多项目 / 查看全部开源项目”入口。

### 期望结果

文案应与实际 UI 一致。例如：

```text

```

或者空状态计数使用与右栏渲染一致的 `Math.min(routeProjects.length, 3)`。
