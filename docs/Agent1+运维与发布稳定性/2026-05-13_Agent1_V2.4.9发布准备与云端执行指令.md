## 4. 云端执行指令

在本地提交推送完成后，于云端执行：

```bash
cd /opt/LarkixMaker
git status -sb
git rev-parse --short HEAD
git rev-parse --short origin/main

GIT_TERMINAL_PROMPT=0 timeout 120s git \
  -c http.version=HTTP/1.1 \
  -c http.lowSpeedLimit=200 \
  -c http.lowSpeedTime=60 \
  fetch origin
echo "fetch_exit=$?"

git rev-parse --short HEAD
git rev-parse --short origin/main

sudo bash scripts/deploy-update.sh

NEW_COMMIT="$(git rev-parse --short HEAD)"
sudo cp /etc/gokottamaker.env /etc/gokottamaker.env.bak.$(date +%Y%m%d-%H%M%S)
if sudo grep -q '^GIT_COMMIT=' /etc/gokottamaker.env; then
  sudo sed -i "s/^GIT_COMMIT=.*/GIT_COMMIT=${NEW_COMMIT}/" /etc/gokottamaker.env
else
  echo "GIT_COMMIT=${NEW_COMMIT}" | sudo tee -a /etc/gokottamaker.env
fi

sudo systemctl restart gokottamaker
sleep 2
curl -fsS http://127.0.0.1:4173/healthz

LATEST="$(ls -1dt /srv/gokottamaker-backups/* | head -n1)"
echo "$LATEST"
cat "$LATEST/manifest.txt"
sudo ls -lah /srv/gokottamaker-data/uploads
```

期望结果：

- `/healthz.versionLabel` 为 `V2.4.9+20260513-1148`。
- `/healthz.gitCommit` 等于云端 `git rev-parse --short HEAD`。
- 最新备份 manifest 中 `source_database_integrity=ok` 与 `backup_database_integrity=ok`。
- 最新备份 manifest 中上传文件数与 `/srv/gokottamaker-data/uploads` 一致。

## 5. 回滚策略

若发布后健康检查失败：

1. 保留发布脚本生成的最新备份目录。
2. 回退 Git 到发布前提交。
3. 使用最近一次 `manifest.txt` 完整性为 `ok` 的备份恢复 `/srv/gokottamaker-data`。
4. 重启 `gokottamaker` 服务并重新执行 `/healthz`。

本轮不直接覆盖用户数据；所有恢复动作都必须先保留 `before-restore` 安全副本。
