## 2. 脚本能力摘要

### `scripts/backup-linux.sh`

新增能力：

- 备份目录精确到秒：`YYYY-MM-DD_HH-MM-SS`。
- 生成 `manifest.txt`，记录源目录、备份目录、数据库大小、上传文件数量、总大小和 SQLite 校验状态。
- 服务器存在 `sqlite3` 时，优先使用 SQLite `.backup` 生成一致性数据库快照。
- 服务器存在 `sha256sum` 时，生成 `manifest.sha256`。
- 保留策略从“仅按天数删除”增强为：默认删除 14 天前备份，但至少保留最近 5 份。

### `scripts/restore-linux.sh`

新增能力：

- 支持 dry-run：

```bash
DRY_RUN=true sudo bash scripts/restore-linux.sh /srv/gokottamaker-backups/YYYY-MM-DD_HH-MM-SS
```

- 恢复前校验备份目录结构。
- 如存在 `manifest.sha256`，执行 checksum 校验。
- 如存在 `sqlite3`，校验备份数据库和恢复后数据库。
- 拒绝恢复到 `/`、`/srv`、`/opt` 等危险目标目录。
- 恢复前保留当前数据目录安全副本。

### `scripts/deploy-update.sh`

新增能力：

- 部署前输出：
  - 当前 commit
  - `server.js` 中版本号
  - systemd 服务状态
  - 当前 `/healthz`
- 备份后写入 `.deploy/last-deploy.env`。
- 部署后输出：
  - 新 commit
  - 新版本号
  - 新 `/healthz`
  - commit 和版本对比
- 任一关键步骤失败时，输出：
  - 当前 commit
  - 部署前 commit
  - 最近备份目录
  - journalctl/status/curl 诊断命令
  - 推荐回滚命令

### `scripts/rollback.sh`

新增能力：

- 默认读取 `.deploy/last-deploy.env` 中的 `PRE_DEPLOY_COMMIT` 回滚。
- 支持显式传入 commit：

```bash
bash scripts/rollback.sh 9263f08
```

- 回滚前自动备份运行数据。
- 代码回滚后重启 systemd 服务并请求 `/healthz`。
- 只回滚代码，不替换 SQLite 和 uploads 数据。

## 4. 本地验证限制

本机 Git Bash 会优先找到 Windows/Android SDK 的 `sqlite3.exe`，该程序不能正确处理 Git Bash 的 `/tmp/...` 路径，因此本地没有完整验证 SQLite `.backup` 路径。

该能力应在腾讯云 Ubuntu 服务器上验证：

```bash
command -v sqlite3
sudo bash scripts/backup-linux.sh
LATEST="$(ls -1dt /srv/gokottamaker-backups/* | head -n1)"
DRY_RUN=true sudo bash scripts/restore-linux.sh "$LATEST"
```

如果服务器没有 `sqlite3`：

```bash
sudo apt-get update
sudo apt-get install -y sqlite3
```
