## decisions

- 缓冲表不设置到文章/项目表的外键。这样即使关联内容被硬删除，缓冲快照仍能显示并由 Owner 清理。
- 缓冲记录采用 `buffered / restored / removed` 状态而非成功后物理删除，保留处置时间；`UNIQUE(content_type, content_id)` 保证重复开关和再次缓冲不会产生重复记录。
- 再次缓冲已恢复内容时，复用同一稳定记录并更新新的原槽位和缓冲时间。
- 缓冲和恢复不修改内容 `publish_status` / `visibility_status`、正文、标题、封面或分类。草稿可以恢复 featured，但仍不会出现在游客公开内容中。
- 槽位冲突只返回 `409 CAROUSEL_SLOT_CONFLICT`；最终槽位始终由 Owner 选择。
- API 返回的缓冲视图使用当前关联内容判断 `available / missing / archived` 和当前聚焦合规性，同时保留初次缓冲时的图片与身份快照。
