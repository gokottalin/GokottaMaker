## 3. knowledge_nodes Contract

Purpose: store derivation knowledge pages as a first-class content type.

Proposed V0 DDL:

```sql
CREATE TABLE IF NOT EXISTS knowledge_nodes (
  id TEXT PRIMARY KEY,
  slug TEXT NOT NULL UNIQUE,
  node_type TEXT NOT NULL DEFAULT 'derivation'
    CHECK (node_type IN ('derivation', 'concept', 'component', 'formula')),
  symbol TEXT NOT NULL,
  title TEXT NOT NULL,
  summary TEXT NOT NULL DEFAULT '',
  markdown TEXT NOT NULL DEFAULT '',
  cover TEXT NOT NULL DEFAULT '',
  accent_color TEXT NOT NULL DEFAULT 'purple'
    CHECK (accent_color IN ('purple', 'blue', 'green', 'amber', 'red', 'neutral')),
  tags TEXT NOT NULL DEFAULT '',
  publish_status TEXT NOT NULL DEFAULT 'draft'
    CHECK (publish_status IN ('draft', 'published', 'archived')),
  visibility_status TEXT NOT NULL DEFAULT 'public'
    CHECK (visibility_status IN ('public', 'unlisted', 'private')),
  deleted_at TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  published_at TEXT,
  CHECK (length(id) BETWEEN 2 AND 97),
  CHECK (length(slug) BETWEEN 2 AND 80),
  CHECK (slug = lower(slug)),
  CHECK (slug NOT GLOB '*[^a-z0-9-]*'),
  CHECK (length(symbol) BETWEEN 1 AND 80),
  CHECK (length(title) BETWEEN 1 AND 160),
  CHECK (length(summary) <= 500),
  CHECK (length(cover) <= 512),
  CHECK (length(tags) <= 800)
);

CREATE INDEX IF NOT EXISTS idx_knowledge_nodes_public
  ON knowledge_nodes(deleted_at, publish_status, visibility_status, node_type, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_knowledge_nodes_slug_public
  ON knowledge_nodes(slug, deleted_at, publish_status, visibility_status);

CREATE INDEX IF NOT EXISTS idx_knowledge_nodes_symbol
  ON knowledge_nodes(symbol);
```

Field contract:

| Field | API field | V0 rule |
| --- | --- | --- |
| `id` | `id` | Stable internal id; may equal slug at creation, but future slug repair must not rewrite revisions. |
| `slug` | `slug` | Public route and shortcode target. Must match `^[a-z0-9][a-z0-9-]{1,79}$` in validators. |
| `node_type` | `nodeType` | DB reserves future types; V0 API/CMS only accepts `derivation`. |
| `symbol` | `symbol` | Formula variable or engineering symbol, e.g. `D.boost`, `Vin`, `Lnom`. Not unique. |
| `title` | `title` | Human page title. |
| `summary` | `summary` | SEO/list summary. Draft may be empty; publishing should require useful text. |
| `markdown` | `markdown` | Node body; supports Agent9 derive shortcodes. Draft may be empty; publishing should require content. |
| `cover` | `cover` | Existing `assets/`, `uploads/`, or HTTP URL only; no data URLs. |
| `accent_color` | `accentColor` | One of `purple`, `blue`, `green`, `amber`, `red`, `neutral`. |
| `tags` | `tags` | V0 comma-separated string. `knowledge_node_tags` is deferred to V1. |
| `publish_status` | `publishStatus` | `draft`, `published`, `archived`. |
| `visibility_status` | `visibilityStatus` | `public`, `unlisted`, `private`. |
| `deleted_at` | `deletedAt` | Soft delete marker. V0 hard delete remains closed. |
| `created_at` | `createdAt` | Creation timestamp. |
| `updated_at` | `updatedAt` | Last save timestamp. |
| `published_at` | `publishedAt` | First publication timestamp; do not reset on draft saves. |

Public read rules:

- List APIs return only `deleted_at IS NULL AND publish_status='published' AND visibility_status='public'`.
- Detail APIs may return `visibility_status='unlisted'` by direct slug, but unlisted nodes must not enter public list, sitemap, or RSS.
- `draft`, `archived`, `private`, and soft-deleted nodes return public `404` without leaking title, summary, markdown, revisions, or audit details.
- V0 keeps derivation nodes out of `/api/content` unless a later API slice explicitly opens that change.

CMS/write rules:

- API payload and response must use canonical `publishStatus` and `visibilityStatus`.
- A transition to `publishStatus='published'` should validate non-empty `title`, `summary`, and `markdown`.
- V0 may accept old `status` or `visibility` aliases only on admin input during transition; public API must not return aliases.

## 4. knowledge_node_revisions Contract

Purpose: keep derivation-node history without changing `content_revisions`.

Proposed V0 DDL:

```sql
CREATE TABLE IF NOT EXISTS knowledge_node_revisions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  node_id TEXT NOT NULL,
  node_slug TEXT NOT NULL,
  node_title TEXT,
  revision_reason TEXT NOT NULL DEFAULT 'save',
  snapshot_json TEXT NOT NULL,
  source_updated_at TEXT,
  actor_user_id INTEGER,
  actor_username TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_knowledge_node_revisions_node
  ON knowledge_node_revisions(node_id, created_at DESC, id DESC);

CREATE INDEX IF NOT EXISTS idx_knowledge_node_revisions_created_at
  ON knowledge_node_revisions(created_at DESC);
```

Revision reasons:

- `save`
- `publish`
- `unpublish`
- `archive`
- `soft_delete`
- `restore`
- `before_revision_restore`

Revision rules:

- Write a revision before overwriting, soft-deleting, restoring, or revision-restoring a node.
- `snapshot_json` must include the full node API shape and a compact outgoing link summary.
- Do not add a foreign key to `knowledge_nodes` in V0; historical snapshots should survive node deletion/restore workflows.
- Revision restore must create a `before_revision_restore` snapshot before applying the old snapshot.

## 5. knowledge_links Contract

Purpose: persist the formula-variable derivation graph from raw Markdown shortcodes.

Proposed V0 DDL:

```sql
CREATE TABLE IF NOT EXISTS knowledge_links (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_type TEXT NOT NULL
    CHECK (source_type IN ('post', 'project', 'knowledge_node')),
  source_id TEXT NOT NULL,
  source_slug TEXT NOT NULL DEFAULT '',
  target_slug TEXT NOT NULL,
  label TEXT NOT NULL,
  color_token TEXT NOT NULL DEFAULT 'purple'
    CHECK (color_token IN ('purple', 'blue', 'green', 'amber', 'red', 'neutral')),
  link_kind TEXT NOT NULL DEFAULT 'derive'
    CHECK (link_kind IN ('derive', 'reference', 'depends_on')),
  ordinal INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CHECK (length(source_id) BETWEEN 1 AND 120),
  CHECK (length(source_slug) <= 120),
  CHECK (length(target_slug) BETWEEN 2 AND 80),
  CHECK (target_slug = lower(target_slug)),
  CHECK (target_slug NOT GLOB '*[^a-z0-9-]*'),
  CHECK (length(label) BETWEEN 1 AND 80)
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_knowledge_links_unique_edge
  ON knowledge_links(source_type, source_id, target_slug, link_kind);

CREATE INDEX IF NOT EXISTS idx_knowledge_links_source
  ON knowledge_links(source_type, source_id, ordinal);

CREATE INDEX IF NOT EXISTS idx_knowledge_links_target
  ON knowledge_links(target_slug, link_kind);
```

Field notes:

- `source_type` V0 supports `post` and `knowledge_node`; `project` is reserved and must not be synced unless a later slice opens it.
- `source_id` is the stable id of the source row.
- `source_slug` is a denormalized helper for API/backlink display. It must not be the only source identity.
- `target_slug` is the derive shortcode target and is intentionally not an FK.
- `label` is the escaped visible text from shortcode, e.g. `D.boost`.
- `color_token` uses the Agent7/Agent9 token whitelist.
- `link_kind='derive'` is the only V0 kind created by shortcode extraction.
- `ordinal` stores the first occurrence order in the source Markdown.

Sync rules:

- Extract links from raw Markdown, not rendered HTML.
- Ignore fenced code blocks, inline code, and LaTeX math regions.
- Support `{{derive:slug|label|color}}` and `{{derive:slug|label}}`.
- Unknown color tokens should be rejected by admin validation or normalized to `purple` with a warning; do not persist arbitrary token names.
- V0 stores one unique edge per `source_type + source_id + target_slug + link_kind`. Repeated references update `ordinal` to first occurrence.
- Dangling targets are allowed. Public APIs must not reveal draft, private, archived, or soft-deleted target content.
- Saving a knowledge node should replace that source's old `knowledge_links` set inside the same transaction as node save/revision/audit.
- Syncing links from posts is allowed only when the post save path is explicitly opened by a later slice; S02 must not edit post save behavior unless governance opens it.

## 6. public_focus_mode Contract

Purpose: store focused public-site mode without deleting hidden content.

Storage:

```text
site_settings.key = 'public_focus_mode'
```

Default JSON:

```json
{
  "enabled": false,
  "primaryScope": "power-electronics",
  "visibleScopes": ["home", "power-electronics", "derivations"],
  "hiddenScopes": ["analog", "stm32", "esp32", "projects"],
  "hideMiniappsFromPrimaryNav": true,
  "hideAdminFromPublicNav": true,
  "noindexHiddenLandingPages": true,
  "noindexHiddenDetailPages": false,
  "homepageMode": "focused",
  "bannerCopy": ""
}
```

Rules:

- `public_focus_mode` is separate from `site_layout`.
- Migration must use `INSERT OR IGNORE` or equivalent; do not overwrite an existing operator-edited setting.
- Default `enabled:false` is mandatory. Running migrations must not hide current public pages.
- Enabling focus mode is an admin/API/frontend behavior in later slices, not a migration side effect.
- Hidden scopes are hidden from primary navigation/home promotion and may be removed from sitemap/noindexed according to SEO slice rules.
- Hidden content and old detail pages are not deleted.

## 7. Audit Contract

Use existing `audit_logs`.

Recommended V0 audit actions:

| Action | entity_type | entity_id | Metadata minimum |
| --- | --- | --- | --- |
| `knowledge_node_save` | `knowledge_node` | node id | `slug`, `publishStatus`, `visibilityStatus`, `accentColor`, `linksCount`, `danglingCount` |
| `knowledge_node_soft_delete` | `knowledge_node` | node id | `slug`, `symbol` |
| `knowledge_node_restore` | `knowledge_node` | node id | `slug`, `symbol` |
| `knowledge_node_revision_restore` | `knowledge_node` | node id | `revisionId`, `slug` |
| `knowledge_links_sync` | `knowledge_links` | source id | `sourceType`, `sourceId`, `linksCount`, `danglingCount` |
| `public_focus_mode_save` | `site_setting` | `public_focus_mode` | `enabled`, `visibleScopes`, `hiddenScopes` |

Audit rules:

- Do not store full markdown, passwords, CSRF tokens, session tokens, `.env` values, production paths, or base64 uploads in audit metadata.
- Node save, revision write, link sync, and audit write should be one transaction where possible.
- If `knowledge_links_sync` is folded into `knowledge_node_save`, the save metadata must still include link counts and dangling counts.

## 9. Rollback and Compatibility Assumptions

The current migration runner has no `down` migrations. Rollback is therefore operational, not schema-down by default.

Assumptions:

- `011`, `012`, and `013` must be additive and forward-compatible.
- Old code must continue to run if the new tables or `public_focus_mode` row exist.
- Code rollback should not require dropping the new tables.
- If data is corrupted, rollback requires Agent1-controlled backup/restore, not ad hoc SQLite edits.
- Production or quasi-production migration requires database and uploads backup, backup integrity verification, and restore dry-run before execution.
- `public_focus_mode.enabled` must remain false after migration smoke unless a later CMS/API/frontend slice explicitly enables it.

S02 must document:

- exact `DATA_DIR`
- exact migration command
- resulting `schema_migrations` rows
- SQLite `PRAGMA integrity_check`
- whether old `/healthz` and `/api/content` behavior stayed compatible
- whether any runtime data outside the isolated directory was touched
