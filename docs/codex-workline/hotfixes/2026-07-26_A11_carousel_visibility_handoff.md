## root_cause

`/api/content` did not expose `publicFocusMode`. The visitor script therefore
used its local fallback, which incorrectly set `enabled:true`, while migration
`013_public_focus_mode_default.js` and the stored site setting both specify
`enabled:false`.

The unintended focus filter removed all four real featured items because none
matched the current power-electronics tokens. The visitor then rendered the
synthetic focus fallback instead of the four CMS-selected items.

## visitor_visibility_contract

Evaluate the following reasons in the listed order. The first matching reason
wins.

| reason code | CMS text | condition | recommended action |
| --- | --- | --- | --- |
| `VISITOR_HIDDEN_DELETED` | 游客端已隐藏：内容位于回收站 | `deletedAt` is present | 取消轮播；如需展示，先恢复内容 |
| `VISITOR_HIDDEN_UNPUBLISHED` | 游客端已隐藏：内容尚未发布 | post `publishStatus !== "published"` or project `visibilityStatus !== "published"` | 发布后保留，或取消轮播 |
| `VISITOR_HIDDEN_PROJECT_OFFLINE` | 游客端已隐藏：项目尚未上线 | project `statusKey !== "online"` | 设为已上线后保留，或取消轮播 |
| `VISITOR_HIDDEN_FOCUS_SCOPE` | 游客端已隐藏：不属于当前电力电子聚焦范围 | focus mode is enabled and the item does not match the focus tokens | 建议取消轮播；仅在内容确属电力电子时补充准确分类或标签 |
| `VISITOR_HIDDEN_LIMIT` | 游客端已隐藏：排序后超出前 4 项 | otherwise eligible, but not in the first four items after visitor sorting | 调整槽位或取消轮播 |
| `VISITOR_VISIBLE` | 游客端可见 | item survives every rule above and is in the first four | no cleanup action |

The focus token check must use the same corpus and tokens as `main.js`:

- corpus: `categoryKey`, `category`, `title`, `excerpt`, `summary`, `tags`,
  `markdown`, `id`, and `slug`, joined and lower-cased
- tokens: `power-electronics`, `电力电子`, `开关电源`, `boost`, `buck`,
  `flyback`, `占空比`, `纹波`, `电感`, `mosfet`, and `power supply`

Visitor ordering is:

1. include posts and projects that pass their public-state rules
2. when focus mode is enabled, keep only focus-token matches
3. keep items with `featured=true`
4. sort by numeric `featuredOrder` ascending
5. keep the first four

CMS cleanup must only set `featured=false`. It must not delete or archive the
post/project. The confirmation text must explicitly say that the article or
project body will remain.

- Missing or invalid focus-mode data fails open with `enabled:false`, preserving
  public content instead of silently hiding it.
- Hidden CMS slots use stable machine-readable reason codes and separate Chinese
  display text.

## risks

  Chinese text would allow visitor and CMS behavior to drift.
- Future changes to the focus corpus or tokens must update this contract and the
  CMS in the same change.
