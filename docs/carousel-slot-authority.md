# Hero 轮播槽位权威源

## 数据模型

`hero_carousel_slots` 是 Hero 的唯一配置源，固定使用 `0..3` 四个物理槽位，对应 CMS
显示的第一张至第四张。

- `slot` 主键保证不同内容类型也不能占用同一位置。
- `UNIQUE(content_type, content_id)` 保证同一内容不能占用多个位置。
- `posts/projects.featured*` 仅保留兼容镜像，不参与 Hero 查询。
- 文章发布状态与槽位配置相互独立，发布不会自动获得槽位。

## 历史冲突

迁移 `026_hero_carousel_slots` 只迁移无冲突的合法槽位。重复或越界声明写入
`hero_carousel_slot_conflicts`，对应槽位保持为空，不自动覆盖、交换、挤位或重排。
CMS 排布页显示冲突记录，作者根据文章本体和历史配置手动决定后续安排。

迁移不删除文章，不改变文章的发布状态。

## 游客展示

`/api/content.heroCarousel` 只从四槽表生成，再叠加发布状态、归档状态和聚焦模式的游客可见性。
游客端不再使用推荐优先级、发布时间、静态 Hero 文案或兜底文章补位。没有可见槽位时，Hero
整体隐藏。

## CMS

- 轮播管理器读取 `carousel.activeItems`，不再从文章列表推测槽位。
- 槽位冲突返回 `409` 和稳定 `CAROUSEL_SLOT_CONFLICT` 原因码，并包含占用内容名称。
- 不提供自动替换；释放旧槽位与安排新内容是两个显式动作。
- 聚焦模式唯一开关位于排布页，底层访问与写入限制保持全局生效。
