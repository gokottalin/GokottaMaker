# Agent5 内容质量检查清单

生成时间：2026-05-05 16:30
适用范围：文章发布、项目上线、CMS 保存前校验、人工内容审阅。

## 1. 文章发布检查

| 检查项 | 必须 | 通过标准 |
|---|---|---|
| 标题 | 是 | 包含技术对象和收益点，不使用空泛标题 |
| 分类 | 是 | 只能是 `模拟电子`、`STM32`、`ESP32`、`开源项目` |
| 摘要 | 是 | 40-80 个中文字符，能独立说明文章价值 |
| 标签 | 是 | 4-8 个，来自受控词表，无重复同义词 |
| 封面 | 是 | 与技术对象相关，alt 能描述主题 |
| 目标 | 是 | 说明本文解决什么问题、适用环境和验证结果 |
| 原理 | 是 | 解释关键概念、约束和取舍 |
| 电路/代码 | 是 | 至少包含电路、参数、配置或代码之一 |
| 调试与验证 | 是 | 说明如何判断结果正确 |
| 常见问题 | 是 | 至少 2 个工程问题，每个包含现象或处理方向 |
| 扩展阅读 | 是 | 至少 2 个前置/后续主题或相关项目 |
| SEO 描述 | 是 | 70-110 个中文字符，避免关键词堆砌 |

## 2. 项目上线检查

| 检查项 | 必须 | 通过标准 |
|---|---|---|
| 项目状态 | 是 | 明确规划中、开发中或已上线 |
| 设计目标 | 是 | 说明场景、指标和约束 |
| 系统结构 | 是 | 能看出硬件、固件、结构和调试边界 |
| BOM | 是 | 至少列出关键器件或 BOM 开放计划 |
| 原理图 | 是 | 说明核心电路和关键保护 |
| PCB | 是 | 说明布局、走线、散热或安装约束 |
| 固件 | 是 | 说明模块划分或后续开放计划 |
| 外壳与装配 | 建议 | 有机械结构时必须补充 |
| 调试记录 | 是 | 至少记录一个验证点或风险点 |
| 标签 | 是 | 5-10 个，包含项目类型、技术对象和资料形态 |
| 资料链接 | 建议 | repo/BOM/docs 未开放时不要填假链接 |

## 3. SEO 检查

| 页面 | 检查项 |
|---|---|
| 首页 | title、description、canonical、OG 是否表达站点定位 |
| 分类页 | title、description 是否按栏目动态更新 |
| 文章页 | title、description、canonical、OG、JSON-LD 是否随文章更新 |
| 项目页 | title、description、canonical、OG、JSON-LD 是否随项目更新 |
| RSS | 标题、链接、摘要、发布日期是否正确 |
| Sitemap | 是否包含公开文章和公开项目 |

## 4. 标签检查

标签必须满足：

- 平台名使用官方大小写：`STM32`、`ESP32`。
- 技术缩写大写：`ADC`、`DMA`、`MQTT`、`BOM`、`PCB`、`OTA`。
- 中文标签保持短词：`低功耗`、`调试`、`校准`。
- 不使用泛标签：`技术`、`教程`、`硬件`。
- 不把标签写成句子。

## 5. 发布前人工复核流程

1. 按本文清单检查字段完整性。
2. 本地打开详情页，确认标题、目录、标签、相关内容正常。
3. 打开分类页，确认文章出现在正确栏目。
4. 检查 RSS 和 Sitemap 是否包含已发布内容。
5. 确认图片可加载，封面与内容主题一致。

## 6. 后续 CMS 接入建议

Agent3 可将本文拆成管理端保存前提示：

- 标题为空或过短时提示。
- 摘要为空或过长时提示。
- tags 少于 4 个或多于 8 个时提示。
- Markdown 缺少 `## 常见问题` 或 `## 扩展阅读` 时提示。
- 项目缺少 `## BOM`、`## 原理图`、`## PCB`、`## 固件`、`## 调试记录` 时提示。
