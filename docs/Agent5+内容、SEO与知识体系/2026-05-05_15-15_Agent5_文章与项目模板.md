# Agent5 文章与项目模板

生成时间：2026-05-05 15:15  
适用范围：技术文章、项目文档、CMS 写作提示、Markdown 导入规范。

## 1. 技术文章模板

适用于模拟电子、STM32、ESP32 三类教程和工程记录。

```markdown
# 标题

用 1-2 段说明问题场景、读者能获得什么、适用边界。避免只写背景，第一屏就要让读者知道本文解决什么工程问题。

## 目标

- 本文解决什么问题
- 适用硬件/软件环境
- 最终可以验证的结果

## 原理

解释关键概念、约束和取舍。技术文章不只给结论，也要解释为什么这样选。

## 电路/代码

给出核心电路、参数、代码片段或配置。代码块需要能独立说明用途，不贴无法理解的大段工程文件。

## 调试与验证

说明如何测量、如何判断结果正确、常见异常表现。能给示波器、串口日志、功耗读数或误差范围时优先给。

## 常见问题

- 问题 1：现象、原因、处理方式。
- 问题 2：现象、原因、处理方式。

## 扩展阅读

- 前置知识
- 相关项目
- 后续文章
```

## 2. 技术文章字段规范

| 字段 | 要求 |
|---|---|
| `title` | 包含对象和收益点，例如 `STM32 ADC 采样时间如何影响高阻信号源精度` |
| `category` | 只能使用 `模拟电子`、`STM32`、`ESP32`、`开源项目` |
| `categoryKey` | 对应 `analog`、`stm32`、`esp32`、`projects` |
| `excerpt` | 40-80 个中文字符，说明场景、方法和读者收益 |
| `readTime` | 当前可人工填写；Agent3 后续可按字数估算 |
| `date` | 发布日期，不替代 `created_at` 或 `updated_at` |
| `tags` | 4-8 个受控标签，逗号分隔 |
| `cover` | 优先使用与内容对象相关的真实封面，不使用无关氛围图 |

## 3. 文章质量检查

发布前至少满足：

| 检查项 | 通过标准 |
|---|---|
| 场景清楚 | 开头说明为什么需要这篇文章 |
| 目标可验证 | 读者知道完成后能测到什么、跑通什么 |
| 原理有取舍 | 不只给参数，也解释参数选择理由 |
| 有工程细节 | 包含电路、配置、代码、测量或调试之一 |
| 有常见问题 | 至少列出 2 个容易踩坑点 |
| 有扩展阅读 | 至少预留前置知识或后续文章 |
| 标签规范 | 标签来自受控词表，且没有重复同义词 |

## 4. 项目文档模板

适用于开源项目详情页和项目日志。

```markdown
# 项目名称

## 项目状态

- 当前阶段：
- 最新版本：
- 已完成：
- 下一步：

## 设计目标

- 使用场景
- 关键指标
- 约束条件

## 系统结构

说明模块划分、信号流、电源流和通信关系。

## BOM

列出关键器件、替代料、采购注意事项。正式项目建议后续提供独立 BOM 文件链接。

## 原理图

说明核心电路、保护设计、接口定义和关键取舍。

## PCB

说明布局约束、走线重点、散热、安装孔和调试点。

## 固件

说明工程结构、构建方式、主要模块和升级方式。

## 外壳与装配

说明外壳文件、安装步骤、装配注意事项。

## 调试记录

记录问题、定位过程、修复方案和版本记录。项目价值很大一部分来自这些真实过程。
```

## 5. 项目字段规范

| 字段 | 要求 |
|---|---|
| `title` | 使用项目正式名称 |
| `statusKey` | 只能使用 `planned`、`development`、`online` |
| `summary` | 40-90 个中文字符，说明项目用途和可复现资料 |
| `license` | 明确许可证，未知时先写规划值并在文档说明 |
| `version` | 已上线项目建议使用语义版本或硬件版本，例如 `HW v0.1` |
| `progress` | 0-100，规划中项目可以低于 30 |
| `repoUrl/bomUrl/docsUrl` | 未公开时可为空，不填占位假链接 |
| `tags` | 5-10 个受控标签 |

## 6. 项目质量检查

项目从“概述”升级到“可复现文档”前至少满足：

| 检查项 | 通过标准 |
|---|---|
| 状态明确 | 读者知道项目是规划中、开发中还是已上线 |
| 资料边界清楚 | 未开放资料明确说明，已开放资料有链接 |
| 模块拆分完整 | 能看出硬件、固件、结构和调试边界 |
| BOM 有入口 | 至少列出关键器件或说明 BOM 开放计划 |
| 调试记录存在 | 至少记录一个问题或验证点 |
| 标签规范 | 标签能支持搜索和相关项目推荐 |

## 7. Markdown 约束

当前渲染器支持：

- `#`、`##`、`###` 标题
- 段落
- 无序列表
- 引用块
- fenced code block
- 行内链接、图片、加粗、行内代码

当前暂不依赖：

- 表格
- 脚注
- 数学公式
- 复杂 HTML
- Mermaid

如果内容确实需要表格、提示块、图片说明或公式，先记录为 Markdown 渲染器增强需求，再由 Agent4/Agent2 协作实现。
