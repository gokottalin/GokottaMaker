# Agent5 SEO 字段需求

生成时间：2026-05-06 13:25
项目版本：`V2.1.1+20260506-1205`
面向协作：Agent2、Agent3、Agent4

## 1. 当前判断

当前站点已有 RSS、Sitemap、Robots、基础 meta、详情页动态 SEO 和 JSON-LD 的前台能力。但从长期 SEO 和 CMS 内容生产看，字段还不够明确。下一步应把 SEO 从“前台临时推导”升级为“内容模型字段 + CMS 校验 + 前台输出”的闭环。

## 2. Post 字段需求

建议文章内容对象在现有字段外，逐步补齐这些 SEO 字段：

| 字段 | 类型 | 必填 | 来源 | 用途 |
|---|---|---|---|---|
| `seoTitle` | string | 建议 | CMS 手填，默认 `title` | `<title>`、`og:title` |
| `seoDescription` | string | 建议 | CMS 手填，默认 `excerpt` | meta description、OG、RSS 摘要 |
| `canonicalPath` | string | 可选 | 系统生成，CMS 可只读 | canonical、Sitemap |
| `coverAlt` | string | 建议 | CMS 手填，默认 `${title}封面` | 图片 SEO、无障碍 |
| `updatedAt` | string | 建议 | 后端维护 | Sitemap lastmod、JSON-LD |
| `publishedAt` | string | 建议 | 发布时写入 | RSS pubDate、JSON-LD |
| `relatedIds` | string[] | 可选 | CMS 手选或自动推荐 | 内链、相关内容 |
| `topicKey` | string | 可选 | CMS 选择 | 专题页和路线图归档 |

## 3. Project 字段需求

建议项目内容对象补齐：

| 字段 | 类型 | 必填 | 来源 | 用途 |
|---|---|---|---|---|
| `seoTitle` | string | 建议 | CMS 手填，默认 `title` | 项目详情 SEO |
| `seoDescription` | string | 建议 | CMS 手填，默认 `summary` | 项目详情描述 |
| `coverAlt` | string | 建议 | CMS 手填 | 图片 SEO、无障碍 |
| `publishedAt` | string | 建议 | 项目上线时写入 | Sitemap、JSON-LD |
| `updatedAt` | string | 建议 | 后端维护 | 项目更新和 Sitemap |
| `repoUrl` | string | 可选 | CMS 手填 | JSON-LD sameAs、项目资料 |
| `releaseNotesUrl` | string | 可选 | CMS 手填 | 项目版本化 |
| `relatedPostIds` | string[] | 可选 | CMS 手选 | 项目到文章内链 |

## 4. 分类与标签字段需求

建议建立受控分类/标签契约，先文档化，后续由 Agent2 数据模型支持。

| 对象 | 字段 | 用途 |
|---|---|---|
| category | `name` | 显示名，例如 `STM32` |
| category | `key` | 稳定键，例如 `stm32` |
| category | `description` | 分类页 meta description 和栏目说明 |
| category | `priority` | Sitemap priority 或导航排序 |
| tag | `name` | 显示名 |
| tag | `slug` | 未来标签页 URL |
| tag | `kind` | `platform`、`topic`、`workflow`、`format` |
| tag | `description` | 未来标签页说明 |

## 5. JSON-LD 输出需求

### 文章页

文章页推荐使用 `TechArticle`。

必要字段：

- `headline`
- `description`
- `image`
- `url`
- `datePublished`
- `dateModified`
- `keywords`
- `author`
- `publisher`

### 项目页

项目页推荐使用 `CreativeWork`，若项目资料足够完整，可后续演进为更具体类型。

必要字段：

- `name`
- `description`
- `image`
- `url`
- `license`
- `datePublished`
- `dateModified`
- `keywords`
- `sameAs`：可使用 `repoUrl`

## 6. RSS 字段需求

RSS item 建议使用：

| RSS 字段 | 当前来源 | 目标来源 |
|---|---|---|
| title | `title` | `seoTitle || title` |
| link | 动态 URL | `canonicalPath` |
| guid | 动态 URL | `canonicalPath` |
| description | `excerpt` | `seoDescription || excerpt` |
| pubDate | `date` | `publishedAt || date` |
| category | `category` | `category + tags` |

Channel 建议补：

- `language: zh-CN`
- `lastBuildDate`
- `ttl`

## 7. Sitemap 字段需求

Sitemap 需要：

| 页面类型 | URL 来源 | lastmod 来源 | priority |
|---|---|---|---:|
| 首页 | 固定 | 最新公开内容时间 | 1.0 |
| 分类页 | category key | 分类下最新内容时间 | 0.8 |
| 文章页 | `canonicalPath` | `updatedAt || publishedAt || date` | 0.7 |
| 项目页 | `canonicalPath` | `updatedAt || publishedAt || date` | 0.7 |

## 8. CMS 校验需求

Agent3 管理端建议增加轻量提示，不阻塞保存，但阻塞发布：

| 发布校验 | 建议 |
|---|---|
| `title` 为空 | 阻塞发布 |
| `excerpt/summary` 为空 | 阻塞发布 |
| `tags` 少于 4 个 | 发布前警告 |
| `seoDescription` 超过 120 中文字符 | 发布前警告 |
| Markdown 缺少 `## 常见问题` | 发布前警告 |
| Markdown 缺少 `## 扩展阅读` | 发布前警告 |
| 项目缺少 `## BOM`、`## 原理图`、`## PCB`、`## 固件`、`## 调试记录` | 项目上线前警告 |

## 9. Agent 分工建议

| 任务 | 主要 Agent | Agent5 提供 |
|---|---|---|
| 字段入库和 API 输出 | Agent2 | 字段定义、默认值规则 |
| CMS 表单和发布校验 | Agent3 | 校验清单、文案 |
| 前台 meta/JSON-LD 渲染 | Agent4 | 字段映射、SEO 规则 |
| RSS/Sitemap 生成 | Agent2 | 字段优先级和 lastmod 规则 |
| 标签/术语治理 | Agent5 | 受控词表 |

## 10. 落地顺序

1. 先不改数据库，只在文档中确认字段契约。
2. Agent2 将 `seoTitle/seoDescription/coverAlt/publishedAt/updatedAt` 加入模型和 API。
3. Agent3 在 CMS 中展示字段，提供默认值和发布前检查。
4. Agent4 前台优先使用 SEO 字段，缺失时回退到现有字段。
5. Agent5 每月复核标签、术语、内链和路线图执行情况。
