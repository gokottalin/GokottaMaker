## 2. 当前结论

GokottaMaker 已经具备技术内容网站的骨架：4 个内容方向、4 篇示例文章、4 个项目条目、文章详情页、项目详情页、分类页、RSS、Sitemap、Robots 和基础 meta 描述。

但它还没有形成“可长期沉淀的电子技术知识库”。当前内容更像演示样例，缺少稳定的信息架构、标签词表、文章模板、项目文档模板、SEO 字段契约、内链策略和选题节奏。尤其是文章详情页仍使用通用 `<meta name="description">`，`post.js` 只更新 `document.title`，未同步 description、canonical、Open Graph、结构化数据；分类页和项目页也缺少按当前分类/项目生成的 SEO 文案。

Agent 5 的优先级应先解决“体系”和“规范”，再批量扩充文章。否则内容越多，分类、标签、slug、标题和摘要越容易散，后续迁移到正式标签模型和 CMS 工作流时成本会变高。

## 6. P0 任务细化

### P0-1：内容分类树与栏目定位

目标：让每一篇文章和每一个项目都能稳定归类，避免后续内容增长后出现“分类随手填、标签随手造”的问题。

建议一级栏目保持现有 4 个方向：

| 栏目 | 定位 | 适合内容 |
|---|---|---|
| 模拟电子 | 从电路指标到真实测量的模拟前端知识 | 运放、滤波、电源、采样前端、噪声、保护、测量 |
| STM32 | 面向工程实践的 MCU 外设、驱动和调试体系 | ADC、DMA、定时器、通信接口、低功耗、Bootloader、调试 |
| ESP32 | 联网节点、低功耗、传感器和 OTA 维护 | Wi-Fi、MQTT、Deep Sleep、传感器、电池、OTA、本地存储 |
| 开源项目 | 可复现的开源硬件项目文档 | 需求、方案、BOM、原理图、PCB、固件、外壳、调试记录 |

建议二级主题：

| 一级栏目 | 二级主题 |
|---|---|
| 模拟电子 | `filter`、`op-amp`、`power`、`adc-front-end`、`noise`、`protection`、`measurement` |
| STM32 | `adc`、`dma`、`timer`、`uart`、`i2c`、`spi`、`rtos`、`bootloader`、`debug` |
| ESP32 | `low-power`、`wifi`、`mqtt`、`sensor-node`、`ota`、`storage`、`battery` |
| 开源项目 | `audio`、`power-supply`、`measurement-tool`、`smart-home`、`firmware`、`mechanical` |

评分：97。原因：这是后续标签模型、CMS 筛选、分类页 SEO 和选题规划的共同底座。

### P0-2：标签词表与命名规范

目标：让标签成为知识检索入口，而不是文章末尾的随意关键词。

建议标签分四类：

| 标签类型 | 示例 | 规则 |
|---|---|---|
| 平台/芯片 | `STM32`、`ESP32`、`ESP32-C3` | 官方大小写优先，不随意翻译 |
| 技术对象 | `ADC`、`DMA`、`MQTT`、`Sallen-Key`、`GBW` | 缩写统一大写，专有名词统一拼写 |
| 工程环节 | `调试`、`校准`、`低功耗`、`PCB布局`、`BOM` | 中文标签保持 2-6 个字，避免长句 |
| 内容形态 | `设计指南`、`踩坑记录`、`项目日志`、`原理解析` | 用于读者预期管理 |

短期可继续输出逗号文本，例如：

```text
STM32,ADC,DMA,校准,调试,设计指南
```

长期由 Agent2 升级为正式 `tags` 表后，Agent5 负责维护受控词表。

评分：95。原因：当前 tags 只是自由文本字段，越晚规范越难清理。

### P0-3：文章模板

目标：让每篇技术文章都有稳定的学习路径、工程上下文和可复现价值。

建议模板：

```markdown
# 标题

用 1-2 段说明问题场景、读者能获得什么、适用边界。

## 目标

- 本文解决什么问题
- 适用硬件/软件环境
- 最终可验证的结果

## 原理

解释关键概念、约束和取舍。

## 电路/代码

给出核心电路、参数、代码片段或配置。

## 调试与验证

说明如何测量、如何判断结果正确、常见异常表现。

## 常见问题

- 问题 1
- 问题 2

## 扩展阅读

- 前置知识
- 相关项目
- 后续文章
```

评分：93。原因：当前文章结构可读，但还没有形成可复制的技术写作标准。

### P0-4：项目文档模板

目标：让开源硬件项目从“项目介绍”升级为“别人能复现、能二次开发”的工程资料。

```markdown
- 使用场景
- 关键指标
- 约束条件

## 系统结构

模块划分、信号流、电源流和通信关系。

## 原理图

核心电路说明、保护设计、接口定义。

## PCB

布局约束、走线重点、散热和安装。

## 固件

工程结构、构建方式、主要模块。

## 外壳与装配

外壳文件、安装步骤、注意事项。

## 调试记录

问题、定位过程、修复方案和版本记录。
```

评分：92。原因：项目区是 GokottaMaker 的差异化资产，必须比普通博客更重视复现资料。

### P0-5：SEO 标题、描述、slug、封面 alt 规范

建议规范：

| 字段 | 规范 |
|---|---|
| SEO 标题 | 20-32 个中文字符优先，包含核心对象和收益点，例如 `STM32 ADC 采样精度优化：采样时间、DMA 与滤波` |
| Meta 描述 | 70-110 个中文字符，说明场景、方法和读者收益，避免堆关键词 |
| Slug | 小写英文、数字和连字符，长期稳定，例如 `stm32-adc-dma-precision` |
| 摘要 excerpt | 40-80 个中文字符，适合卡片和 RSS |
| 封面 alt | 描述画面和主题，不写“图片”，例如 `STM32 开发板连接示波器进行 ADC 采样调试` |
| 标签 | 4-8 个，包含平台、对象、环节、内容形态 |

评分：91。原因：当前页面已有基础 SEO，但缺少内容侧输入规范，动态详情页也缺少完整字段。

## 12. 当前风险提示

1. 当前 4 篇文章是演示级内容，不能直接支撑“长期知识库”的定位。
2. 标签字段已存在但没有规范，后续迁移为正式标签模型前应先冻结词表。
3. 详情页只动态更新 `document.title`，搜索和社交分享仍会读到通用 description。
4. 分类页 meta 过于通用，无法表达每个栏目独立价值。
5. 项目 Markdown 内容过短，缺少 BOM、原理图、PCB、固件和调试记录，不利于开源硬件复现。
6. 文章之间没有内链和前置知识提示，知识库结构感弱。
7. Markdown 渲染器暂不支持表格、提示块、图片说明和公式，后续电子技术长文会受到限制。
8. 当前 URL 使用 `post.html?id=...` 和 `project.html?id=...`，短期可用，但长期 SEO 更适合稳定语义路径；这需要后端路由和前台协作，不建议 Agent5 单独改。
