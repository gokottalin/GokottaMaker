# CMS 悬浮反馈与文章发布栏

## 目标

文章编辑页使用一个固定在视口右下角的操作栏，并把 CMS 操作结果统一显示为视口级 toast。实现不改变后端发布规则，也不新增第二套文章保存状态机。

## 文章提交

- 文章模式隐藏编辑器中部的通用提交按钮；项目和推导节点仍保留该按钮。
- `保存草稿` 与 `发布文章 / 更新发布` 只负责设置 `publishStatus`，随后调用同一个 `contentForm.requestSubmit()`。
- 页面只注册一个 `contentForm` submit 处理器。操作期间两个文章按钮同时禁用，避免重复提交。
- 任意文章字段变化都写入同一个 `isDirty` 状态；成功后清除，失败后保留，并继续使用既有本地草稿备份。
- 原生表单约束和后端精确校验继续生效。字段阻断既保留浏览器字段定位，也显示持久 toast。

## 操作反馈

- `success`、`info`、普通 `warning` 在 3 秒后渐出。
- `error` 默认持久显示，只能由关闭按钮、同键后续结果或问题修正后的新操作解除。
- toast 按 key 替换；每项操作带递增版本号，旧响应不能覆盖较新的保存或发布结果。
- 请求默认 20 秒超时，超时统一转换为可操作的中文阻断提示。
- 每条 toast 都有图标、文字、可访问角色和键盘可用的关闭按钮；减少动画偏好会取消进入、退出动画。

## 浮层协调

- 桌面展开公式抽屉时，文章发布栏向左避让。
- 1180px 以下公式抽屉改为底部面板，发布栏停靠在其上方。
- 640px 以下，公式抽屉折叠时发布栏停靠在公式入口上方；文章发布栏自身折叠后固定为 `52 x 52`。
- `visualViewport` 提供软键盘偏移和可见高度，安全区域使用 `env(safe-area-inset-*)`。
- toast 固定在视口顶部，层级高于公式抽屉和发布栏，不依赖页面滚动位置。

## 验证

静态与确定性回归：

```powershell
node scripts/test-cms-floating-feedback-publish-bar.js
node scripts/test-formula-authoring-drawer.js
node scripts/test-full-site-dark-theme.js
```

隔离数据浏览器验收覆盖：

- 文章原生字段阻断、后端正文阻断、保存草稿成功、发布成功和更新发布标签。
- 普通提醒 3 秒消退，阻断错误持续显示并可关闭。
- `1440 x 900`、`760 x 900`、`390 x 844` 的固定区几何和横向溢出。
- 浅色、深色、发布栏折叠/恢复、公式抽屉展开/收起组合。
- 软键盘由确定性矩形夹具覆盖；实际桌面浏览器无法唤起移动系统软键盘，运行时由 `visualViewport` 驱动。
