## 2. 根因定位

轮播数据清理后，云端重启仍会重新出现 `opensource-power-amplifier` 占用 slot 3。根因不是 SQL 清理失败，而是 `server.js` 启动阶段的 `reconcileSeedContent()` 会把种子文章重新补回精选状态：

```text
featured = CASE WHEN featured = 0 THEN ? ELSE featured END
featured_order = CASE WHEN featured_order = 0 THEN ? ELSE featured_order END
```

这会覆盖生产库中 CMS 已编辑过的轮播状态。正确原则是：SQLite 生产库为事实来源，种子数据只应参与初始化或补齐空白元数据，不应在服务启动时覆盖 `publish_status`、`featured`、`featured_order`。

## 3. 已完成修复

本地与云端均已修复 `server.js`：

- `reconcileSeedContent()` 不再更新 `publish_status`。
- `reconcileSeedContent()` 不再更新 `featured`。
- `reconcileSeedContent()` 不再更新 `featured_order`。
- 仅在必要时补齐空 `tags`、`created_at`、`published_at`。

云端随后禁用了多余轮播项：

```text
post:opensource-power-amplifier
```

该内容未删除，仅取消首页轮播精选状态。
