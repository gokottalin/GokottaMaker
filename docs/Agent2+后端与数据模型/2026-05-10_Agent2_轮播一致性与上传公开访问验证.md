## 8. 复发根因与代码修复

服务器侧清理 `opensource-power-amplifier` 后，复查仍出现重复 slot 3。根因不是 SQL 清理失败，而是 `server.js` 启动时的 `reconcileSeedContent()` 会把种子文章重新补回轮播：

```text
featured = CASE WHEN featured = 0 THEN ? ELSE featured END
featured_order = CASE WHEN featured_order = 0 THEN ? ELSE featured_order END
```

这违反当前数据原则：SQLite 是生产事实来源，种子文件只用于初始化和开发兜底，不应覆盖 CMS/生产库已编辑的轮播状态。

本地已修改 `server.js`：

- `reconcileSeedContent()` 不再更新 `publish_status`。
- 不再更新 `featured`。
- 不再更新 `featured_order`。
- 仅补齐空 `tags`、`created_at`、`published_at`。

本地验证：

```powershell
node --experimental-sqlite --check server.js
node --experimental-sqlite scripts\check-carousel-db.js --db database\gokottamaker.sqlite
```

结果：

```json
{
  "ok": true,
  "featuredCount": 3,
  "duplicateSlots": [],
  "outOfRange": []
}
```

服务器需要先应用该代码修复，再清理数据库，否则重启仍可能复发。
