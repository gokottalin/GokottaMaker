## 2. 已完成代码项

### 2.1 内容版本历史

新增迁移：

```text
migrations/007_content_revisions.js
```

新增表：

```text
content_revisions
```

记录字段包括：

- `content_type`：`post` 或 `project`
- `content_id`
- `content_title`
- `revision_reason`
- `snapshot_json`
- `source_updated_at`
- `actor_user_id`
- `actor_username`
- `created_at`

触发版本记录的动作：

- 保存文章前记录旧版本。
- 保存项目前记录旧版本。
- 移入回收站前记录旧版本。
- 从回收站恢复前记录旧版本。
- 允许永久删除时，永久删除前记录旧版本。
- 从历史版本恢复前，再记录当前状态。

### 2.2 版本查询与恢复 API

新增管理端 API：

```text
GET  /api/posts/:id/revisions
POST /api/posts/:id/revisions/:revisionId/restore
GET  /api/projects/:id/revisions
POST /api/projects/:id/revisions/:revisionId/restore
```

这些 API 需要管理员登录和 CSRF。当前先完成后端能力，管理端 UI 可由 Agent3 后续接入。

### 2.3 事务化写入

新增 `withTransaction()`，并把以下动作纳入同一事务：

- 内容保存。
- 标签同步。
- 审计日志。
- 内容删除/恢复。
- 历史版本恢复。

这样可以避免正文已写入、标签或审计未写入的半状态。

### 2.4 默认禁用永久删除

新增环境变量：

```text
ALLOW_HARD_DELETE=false
```

默认行为：

- `DELETE /api/posts/:id/hard` 返回 403。
- `DELETE /api/projects/:id/hard` 返回 403。
- 审计日志记录 `*_hard_delete_blocked`。

只有显式设置：

```text
ALLOW_HARD_DELETE=true
```

才允许永久删除。生产环境建议一直保持 `false`。

### 2.5 种子回填进一步收紧

已继续收紧 `reconcileSeedContent()`：

- 种子文章不再覆盖 `publish_status`、`featured`、`featured_order`。
- 种子项目不再覆盖 `visibility_status`、`status`、`status_key`。
- 仅补齐缺失的基础元数据。

生产库仍是事实来源，服务重启不再用种子数据覆盖 CMS 中已编辑的状态。

### 2.6 备份新鲜度与异地备份入口

新增环境变量：

```text
MAX_BACKUP_AGE_HOURS=26
OFFSITE_BACKUP_TARGET=
OFFSITE_BACKUP_MODE=rsync
```

`/api/admin/health` 增加：

- `allowHardDelete`
- `maxBackupAgeHours`
- `offsiteBackupConfigured`
- `backups.ok`
- `backups.warnings`
- `backups.latest.ageHours`
- `backups.latest.fresh`

新增脚本：

```text
scripts/sync-backups-offsite.sh
scripts/check-backups-linux.sh
```

`scripts/backup-linux.sh` 已支持在 `OFFSITE_BACKUP_TARGET` 配置后自动同步异地备份。

## 5. 需要用户对接的内容

### 5.1 异地备份目标

需要你选择一种：

方案 A：另一台 Linux 服务器

需要提供：

- SSH 登录用户。
- 服务器地址。
- 备份目录，例如 `/srv/gokottamaker-offsite-backups`。
- 是否允许当前 VPS 使用 SSH key 免密写入。

配置示例：

```text
OFFSITE_BACKUP_MODE=rsync
OFFSITE_BACKUP_TARGET=backup-user@backup-host:/srv/gokottamaker-offsite-backups
```

方案 B：对象存储

需要提供：

- 对象存储服务商。
- bucket 名称。
- endpoint。
- access key / secret key。
- 是否使用 `rclone`。

配置示例：

```text
OFFSITE_BACKUP_MODE=rclone
OFFSITE_BACKUP_TARGET=gokotta-remote:gokottamaker-backups
```

### 5.2 云端环境变量

需要在 `/etc/gokottamaker.env` 增加或确认：

```text
ALLOW_HARD_DELETE=false
MAX_BACKUP_AGE_HOURS=26
OFFSITE_BACKUP_TARGET=按你的异地备份方案填写
OFFSITE_BACKUP_MODE=rsync 或 rclone
```

### 5.3 定时任务

当前已有每日备份 cron。异地备份配置好后，继续使用原备份脚本即可自动同步。

建议确认：

```bash
cat /etc/cron.d/gokottamaker-backup
```

或确认是否已经安装到系统 cron。

### 5.4 管理端 UI 接入

后端 API 已具备版本历史能力，但 CMS 前端还需要接入：

- 查看历史版本列表。
- 对比当前内容和历史版本。
- 一键恢复历史版本。
- 管理端健康卡展示 `backups.warnings`。

这部分建议交给 Agent3。
