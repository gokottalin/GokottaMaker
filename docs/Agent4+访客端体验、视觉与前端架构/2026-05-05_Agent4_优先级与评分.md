# Agent 4：访客端体验、视觉与前端架构优先级与评分

更新时间：2026-05-05
项目版本基线：V1.5.0+20260504-1655
责任 Agent：Agent 4
责任范围：访客端体验、视觉系统、前端架构、阅读体验、图片资产与移动端表现

## 1. 责任边界

Agent 4 主要负责：

```text
index.html
category.html
projects.html
post.html
project.html
main.js
post.js
styles.css
site.webmanifest
assets/
```

Agent 4 不直接负责：

- 后端认证、CSRF、Session、数据库迁移。
- 管理端 CMS 表单与内容工作流。
- 部署脚本、systemd、备份与回滚。
- 内容选题、文章体系与 SEO 内容策略，但需要为 Agent 5 提供前台展示能力。

如确实需要改动 `server.js`、`data/markdown-renderer.js` 或 API 契约，应先标记为跨 Agent 协作项，并说明影响范围。

## 2. 当前诊断

访客端已经具备完整可用形态：首页 Hero、文章卡片、项目卡片、分类页、项目列表、文章详情、项目详情、目录、Markdown 渲染、跳转链接、基础 SEO、manifest、404 与打印样式均已存在。

当前最主要的问题不是“缺少页面”，而是：

- `styles.css` 体积和职责过大，Hero、卡片、Markdown、响应式、打印样式混在一个文件中。
- 首页 Hero 已经过多轮视觉增强，继续堆单点特效的收益低于架构整理和移动端稳定。
- 图片资源体积偏大：Hero 约 1954KB，概念图约 1693KB，Logo 图约 817KB，封面图约 442KB-640KB。
- 首页搜索只过滤当前首页列表，没有独立搜索页、结果分组、空状态引导和移动端搜索体验。
- 详情页阅读体验仍可增强：阅读进度、图片灯箱、目录当前位置、代码块复制、长文锚点状态。
- 详情页 meta 仍是静态 HTML，严格 SEO 需要 Agent 2/5 参与服务端动态输出。

已验证：

```powershell
node --check main.js
node --check post.js
```

两项均通过。

## 3. 评分口径

总分 10 分，按以下维度评估：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 用户体验影响 | 0-3 | 对访客阅读、浏览、移动端使用的直接影响 |
| 性能与稳定性 | 0-2 | 对首屏速度、布局稳定、资源加载的影响 |
| 可维护性收益 | 0-2 | 对后续前端迭代、样式修改、组件复用的收益 |
| 项目协同价值 | 0-2 | 对其他 Agent 或长期内容增长的支撑 |
| 执行紧急性 | 0-1 | 当前是否容易阻塞后续工作或线上体验 |

优先级划分：

| 优先级 | 分数范围 | 含义 |
|---|---:|---|
| P0 | 9.0-10.0 | 立即处理，直接影响核心访问体验或后续大规模迭代 |
| P1 | 7.5-8.9 | 近期处理，收益明确 |
| P2 | 6.0-7.4 | 中期优化，提升品质和规模化能力 |
| P3 | 4.0-5.9 | 体验增强或锦上添花 |
| P4 | 0-3.9 | 暂缓 |

## 5. 推荐执行顺序

第一批，先做稳定和性能：

1. 拆分 `styles.css`。
2. 制定并执行图片优化方案，至少生成 WebP 和移动端尺寸。
3. 优化移动端 Hero 与顶部导航。
4. 增加详情页阅读进度和目录当前位置。

第二批，做内容增长后的浏览效率：

1. 全站搜索升级。
2. 分类页和项目页筛选/排序。
3. 前台列表渲染逻辑抽取。
4. 卡片系统统一。

第三批，做阅读品质细节：

1. 图片灯箱。
2. 代码块复制。
3. PWA manifest 完整化。
4. 打印样式二轮优化。

## 6. 关键工作说明

### 6.1 CSS 模块化

建议拆分为：

```text
styles/
  base.css
  layout.css
  components.css
  hero.css
  cards.css
  markdown.css
  responsive.css
  print.css
```

短期可继续由 `styles.css` 使用 `@import` 组织，降低 HTML 改动面。长期若迁移 Next.js，再把这些模块变成组件级样式或全局层级样式。

验收标准：

- 首页、分类页、项目页、文章详情、项目详情视觉不回退。
- 移动端 390x844 不出现导航、Hero 文案、卡片文字重叠。
- `prefers-reduced-motion`、focus 样式、print 样式不丢失。

### 6.2 图片优化

当前重点资源体积：

| 资源 | 体积 |
|---|---:|
| `assets/hero/electronics-lab-hero.png` | 1953.7KB |
| `assets/concept/gokottamaker-home-concept.png` | 1693.4KB |
| `assets/logo/gokottamaker-logo.png` | 817.3KB |
| `assets/covers/project-cover.png` | 639.6KB |
| `assets/covers/stm32-cover.png` | 568.7KB |
| `assets/covers/analog-cover.png` | 524.6KB |
| `assets/covers/esp32-cover.png` | 441.7KB |

建议产物：

```text
assets/hero/electronics-lab-hero-1600.webp
assets/hero/electronics-lab-hero-960.webp
assets/covers/*-800.webp
assets/covers/*-480.webp
```

验收标准：

- 首页首屏优先加载合适尺寸 Hero。
- 列表封面使用 `srcset` 或 `<picture>`。
- PNG 原图保留，WebP 作为主要展示格式。
- 不影响管理端上传图片路径。

### 6.3 移动端 Hero

优化方向：

- 限制 Hero 最小和最大高度，避免一屏全被 Hero 占满。
- 小屏减少或收起 Hero 小卡片复杂玻璃效果。
- Hero 主文案、按钮、元信息在 390px 宽度下不挤压。
- 减少移动端动画和大面积透明滤镜的性能压力。

验收标准：

- 390x844、430x932、768x1024 下无重叠。
- Hero 之后能看到下一段内容提示。
- 搜索框和导航可点击区域足够稳定。

### 6.4 阅读增强

建议能力：

- 页面顶部阅读进度条。
- TOC 当前标题高亮。
- 标题锚点复制或点击跳转。
- 代码块复制按钮。
- 图片点击灯箱。

验收标准：

- 无 JS 时正文仍可读。
- 有 JS 时增强功能不改变 Markdown 原始内容。
- 项目详情和文章详情复用同一套增强逻辑。

## 8. 风险与注意事项

- 不要在当前阶段继续无边界堆 Hero 特效，视觉复杂度已经较高。
- CSS 拆分时必须小步验证，避免一次性大重构导致全站样式回退。
- 图片优化不要删除原始 PNG，避免管理端或旧内容引用失效。
- 前台脚本抽取时要保持 `window.GokottaContent` 现有契约不变。
- 涉及 Markdown 渲染能力升级时，要优先保证安全转义，不引入 XSS 风险。

## 9. Agent 4 阶段结论

Agent 4 当前最值得投入的方向是“把已有漂亮页面变得更稳、更快、更可维护”。首页 Hero 已经具备识别度，短期应把优先级从视觉叠加切换到 CSS 模块化、图片优化、移动端稳定和长文阅读效率。这样后续 Agent 5 增加内容、Agent 3 提高发布效率时，访客端不会因为内容规模增长而变慢或变乱。
